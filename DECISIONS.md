# Decision log

Technical decisions in the order they were made, with the evidence behind
each. Every entry names the result that justified it, so each choice can be
defended in the interview. "AI" marks decisions first proposed by the AI
assistant. Review these and confirm you agree with them (see `AI_USE.md`).

| # | Decision | Alternatives considered | Evidence / reason |
|---|----------|------------------------|-------------------|
| D1 | Use **Dataset 2 (MSI occupancy + environmental)**. Problem: estimate room occupancy from environmental sensors (a "virtual occupancy sensor"). | Apple-tree RGB-D, pork-packaging vision | Fits the unit content (regression, ODEs, finite differences, optimisation). Runs on CPU. Occupancy-driven ventilation is a real HVAC energy lever. |
| D2 | **Physics model:** single-zone well-mixed CO2 balance `V dC/dt = 1e6 g N − Q (C − C_out)`. | Multi-zone model; adding temperature/heat balance | Simplest model with physical parameters. Linear in the unknowns, so calibration is a closed-form least-squares problem. |
| D3 | **Calibration** by linear least squares on `N = a dC/dt + b C + c` (equation error). | Nonlinear output-error fit (simulate C, match measured C) | Closed form, fast and unique. Verified to recover V, Q and C_out within 5 % on manufactured data (`tests/test_physics.py`). |
| D4 | **Forward solvers:** Euler, RK4 and exact. Use the exact solution (IIR filter via `lfilter`) for production. | RK4 only | Observed orders were 0.97 (Euler) and 4.14 (RK4), matching theory. The exact solution has no truncation error. The lfilter form is ~40× faster than a Python loop (`reports/results/performance.csv`). |
| D5 | **Resample** irregular (~10 min) env data to a 15-min grid by **linear** interpolation; do not bridge gaps > 45 min. | PCHIP, natural cubic, nearest | Hold-out test on real CO2: linear MAE 7.9 ppm, PCHIP +0.3 ppm, nearest 9.3, cubic 10.0 (`real_resample_holdout.png`). Cubic overshoots on noisy data. |
| D6 | Occupancy target = **time-weighted mean headcount** per interval (zero-order hold between events, capped at 30 min). | Last value; event count | Headcount is a state reported at events, so a time average is the correct interval mean. The cap stops a silent (possibly offline) counter being read as "constant". |
| D7 | **Centre** the occupancy interval on the CO2 timestamp, `[t − dt/2, t + dt/2)`. (AI, from the synthetic study) | Left-labelled `[t, t + dt)` | The left label makes occupancy lead CO2 by dt/2. On synthetic data this biased V by +40 %; centring cut the bias to about +6 % (`alignment.csv`), and all models improved. |
| D8 | **Exclude frozen env sensors** (fewer than 100 unique timestamps) and drop exact re-sent payloads. | Keep all rows | 3 of 5 env sensors re-send one identical payload 11k–59k times. 137k of 179k rows are duplicates (`real_audit_timeline.png`). |
| D9 | **Associate sensors with spaces from the data**, using correlation of CO2 and headcount after removing each series' time-of-week mean. | Trust the location sheet | The sheet ties no working env sensor to a counted space, and its OCC tab is labelled "SpaceFloorIDs Invalid". Removing the shared weekly pattern stops "both busy during office hours" from creating a false match. |
| D10 | Primary pair: sensor **…0869** with space **3e5a14df** (residual r = 0.65, 25 labelled days). Weaker pairs (r = 0.41, 0.33) are **controls**. | Use only the primary pair | The controls are a negative check. If CO2 carried no room-level information, primary and controls would score alike. They don't: forest R² is 0.51 vs 0.27–0.40. |
| D11 | Do **not** use the "Example Data (Do not use)" files. | Use the richer MSI-lab file | The teaching team said not to use them. |
| D12 | **Main validation:** blocked leave-one-week-out CV with 1-day buffers and pooled out-of-fold scoring. Also report a chronological 60/20/20 split. | Random K-fold; chronological only | Random folds leak information through autocorrelation. The chronological test window (6–13 June) fell entirely in the exam period (mean occupancy 0.8 vs 3.7 in training), which makes R² meaningless there. Weekly blocks put every regime in the test data. The chronological split is kept as a regime-shift scenario. |
| D13 | Use **causal features only** (current and past samples). | Centred derivative features | The estimator should be deployable in real time. The physics estimator uses a Savitzky–Golay derivative, which adds 2 samples (30 min) of latency. This is stated as a limitation. |
| D14 | **Keep default hyper-parameters** for the headline results. | Report the best tuned setting | The tuning sweep used the same CV folds, so picking its best would be optimistic. The gain was small anyway (forest R² 0.51 → 0.54, `sens_hyperparameters.csv`). The sweep is reported as sensitivity instead. |
| D15 | Report **MAE and F1 alongside R²**. | R² only | R² depends on the test-set variance and swings wildly under regime shift. MAE is in persons and is what a building operator cares about. |
| D16 | **Interpretation:** predictions are invariant to the assumed generation rate g. V is poorly identified; Q is robust (~0.25 m³/s). | — | Shown in `sens_g_invariance.csv` (predictions identical to 1e-15) and `sens_physics_scheme_grid.csv` (V ranges 23–545 m³ across schemes while Q stays ≈ 0.25 m³/s). The CO2 level term carries the prediction, not the transient term. |
| D17 | Use **scikit-learn MLP**, not PyTorch. | PyTorch MLP | The networks are small tabular regressors and sklearn's MLP is sufficient. It needs one fewer heavy dependency and fits the course notebooks. |
| D18 | Report **balanced accuracy**, not F1 or accuracy, for the occupied state; score all models on a **common** set of intervals. (From the independent review) | F1 (as first reported) | 77 % of labelled intervals are occupied, so a constant "occupied" prediction gets F1 = 0.87, the same as the best model. Balanced accuracy gives 0.5 to any constant prediction. |
| D19 | A 15-min target needs **≥ 50 % minute coverage**. (From the independent review) | Accept any interval with ≥ 1 valid minute | About 8 % of intervals had fewer than 8 valid minutes; a single minute is not an interval mean. |
| D20 | **Disclose** the pair-selection optimism rather than re-select on a held-out period. | Select on the first week only | Only about 25 labelled days exist, so holding out a selection period would leave too little for CV. Reported as a limitation (§5.2). |
| D21 | Learning curve subsamples **labelled** days only. (From the independent review) | All days | Unlabelled days contributed nothing, so the "n days" axis overstated the training data. |
